# «Всё успею» — frontend MVP: реализация и ограничения

React 19 + TypeScript + Vite 7, графики `@unovis/ts` 1.7.1, шрифт `@fontsource-variable/nunito-sans`.
Интерфейс на русском и повторяет утверждённый макет `prototype/`. Сам макет не менялся.
Его CSS (`styles.css`, `worlds.css`, `catalog.css`) и арт-модуль `world-art.js/css` скопированы в `src/`.
Единственное изменение в копии `worlds.css` — селектор hero-сцены, адаптированный под React-обёртку.
Логотипы скопированы в `public/logos/` и доступны по `/logos/...`.

Контракт обмена с сервером — `docs/API.md`. Фронтенд не вводит собственных API и не показывает демо-данные:
баланс, графики, поручения, награды и мир берутся только с сервера.

## Запуск

```sh
cd frontend
npm ci
npm run dev        # http://127.0.0.1:5173, /api проксируется на VITE_BACKEND_ORIGIN (по умолчанию http://127.0.0.1:8000)
npm run typecheck
npm test           # Vitest + Testing Library (jsdom), 34 теста в src/
npm run test:qa    # QA-набор ../tests/frontend (28 тестов) с зависимостями и setup фронтенда
npm run build      # dist/ — его отдаёт FastAPI (FRONTEND_DIST, по умолчанию ../frontend/dist)
```

Для локальной проверки по HTTP backend нужно запускать с `APP_ENV=development` и `COOKIE_SECURE=false`.
Иначе браузер может не сохранить `Secure`-cookie `tfe_csrf`, и мутирующие запросы получат `403 csrf_failed`.

## Структура

- `src/app/` — `App` (выбор экрана: проверка / настройка / вход / выход / приложение), `session` (bootstrap, баланс, вход/выход), `theme`, hash-роутер, `AppShell`, `ThemeSwitch`.
- `src/shared/api/` — `client.ts` (same-origin fetch, CSRF, refresh, Idempotency-Key, `X-Child-Id`), `endpoints.ts`, `types.ts`, `useApi`.
- `src/shared/charts/` — Unovis: `WeekStackChart`, `TimeDonut`, `ProgressLine`, плюс палитра.
- `src/shared/permissions.ts` — UI-зеркало серверных прав.
- `src/features/` — dashboard, activities, timers, time-entries, chores, rewards, world, onboarding, profile, settings, auth.

## Авторизация и сессия

- Вход: `POST /auth/login`. Сессия живёт только в HttpOnly-cookie backend. Токены, пароли и данные не попадают в `localStorage`.
  В `localStorage` хранится только выбранная тема. В `sessionStorage` хранится только выбранный взрослым ребёнок (`X-Child-Id`).
- CSRF: `GET /auth/csrf` при старте; заголовок `X-CSRF-Token` на всех POST/PUT/PATCH/DELETE.
- `401 session_expired` → один `POST /auth/refresh` и один повтор. `403 csrf_failed` → повторный bootstrap CSRF и один повтор.
- Если `GET /me` отвечает 401, приложение дополнительно проверяет `GET /health/ready`. Если установка не готова, показываются шаги настройки из `setup` и `details.missing` вместо бесполезной формы входа.
  Найдено на живом backend: без БД и Supabase он отвечает на `/me` кодом 401, а не 503.
- `503 service_not_configured | schema_missing | auth_unavailable` и отсутствие связи → экран «Приложение ещё настраивается» с подсказками. Секреты в браузере не вводятся.
- Выход: `POST /auth/logout {pause_running_timers:true}`. При любом исходе клиент забывает CSRF-токен, выбранного ребёнка, баланс и маршрут; экраны с данными размонтируются.
  - `503 logout_incomplete`: cookie уже очищены сервером; показывается предупреждение с текстом сервера.
  - Сетевая ошибка: показывается предупреждение и кнопка «Повторить выход».
- После входа вызывается `POST /rewards/evaluate` (идемпотентно, по контракту) — он же даёт баланс для header.

## Права ребёнка и взрослого

Сервер остаётся источником истины. UI использует флаги `me.permissions` (`docs/API.md` §2.1) и прячет или блокирует недоступное.
Отсутствующий флаг (старый backend) считается запретом.

| Флаг | Поведение UI |
|---|---|
| `can_set_workload` | Только с ним показывается выбор «Объём домашнего задания» (ручная запись, сохранение таймера, правка). Без флага поле `workload` **не отправляется** — сервер ставит `normal`. |
| `can_confirm_quality` | Выбор статуса проверки в истории (`PUT /entries/{id}/quality`). Без флага проверенная (confirmed/rejected) запись урока открывается в режиме «Изменить заметку»: дата и время заблокированы, отправляется только `note`. |
| `can_delete_reviewed_entries` | Без флага у проверенных записей вместо «Удалить» показано «Удаляет взрослый». Непроверенные (pending) записи ребёнок редактирует и удаляет полностью. |
| `can_edit_timezone` | Без флага выбор часового пояса в профиле заблокирован и не отправляется в `PATCH /me`. |

Часовой пояс меняет только взрослый, и это **намеренное ограничение безопасности**, а не временное упрощение.
Пояс определяет, к какому календарному дню относятся записи, поручения и окна наград. Если бы ребёнок мог его менять, он мог бы задним числом переносить данные между днями и окнами оценки.

## Экраны и соответствие контракту

- **Мой день** — `GET /dashboard`, `GET /activities`, `GET /analytics/time` (4/8/12 недель; группировка «Категории/Предметы»).
  Stacked bar по неделям пн–вс; неполная неделя помечена `*`. Donut показывает долю учтённого времени за тот же период.
  Первая карточка — предварительный результат периода и дата оценки («ещё не начислено»), а не придуманный процент.
- **Уроки / Прогулка / карточка занятия** — серверный таймер:
  - локальный тик от `elapsed_ms`; повторная синхронизация при возврате на вкладку;
  - `start/pause/reset/save` с `revision` и новым `Idempotency-Key` на действие (тот же ключ только при повторе после сетевой ошибки);
  - `409` → принимается `details.current`;
  - `other_running` → предупреждение с кнопкой паузы другого таймера (без молчаливой паузы);
  - сохранение: выбор даты от `started_on` до сегодня, подтверждение > 4 ч, обязательное исправление > 24 ч.
  - Ручная запись: часы и минуты, 1 мин – 24 ч, дата не позже сегодня.
  - Line chart строится из `GET /activities/{id}/daily-totals`: только даты с записями, по возрастанию, соседние точки соединены. Ось X — календарные дни; прореживаются только подписи оси, точки — никогда. Есть таблица «Посмотреть числа».
  - История: курсорная пагинация (`Показать более ранние записи`), правка с `revision`, удаление с подтверждением.
- **Поручения** — Сегодня / Неделя (7 × `GET /chores?date=`, отмечать можно только сегодня) / Все (архив и возврат).
- **Награды** — окно и база с точными датами, карточки категорий с фактами. Для недостающих дней прогулки — кнопка «Не гулял» (`PUT /day-statuses/walk/{date}`). Итоги прошлых периодов и журнал кошелька с пагинацией.
- **Мой мир** — горизонтальная лента коллекции, каталог с поиском (`POST /worlds` бесплатно), `PUT /me/active-world`.
  - Анимированная сцена пересоздаётся при смене этапа или мира и ставится на паузу при скрытой вкладке.
  - Бесплатный предпросмотр 0–4 работает только на клиенте.
  - Покупка — через диалог подтверждения и `POST /worlds/{code}/purchases` с Idempotency-Key. Цена, предпосылки и баланс приходят только с сервера. Журнал острова — из `events`.
- **Настройки** — создание занятий и поручений (ежедневно / будни / раз в неделю / выбранные дни / без расписания, дата начала ≥ сегодня, необязательная дата окончания), правка своих занятий, архив.
  Режим наград, подключения и список `deferred` берутся из `GET /settings` и только читаются.
- **Профиль** — имя, класс (1–11), часовой пояс (по правам), выбор ребёнка для взрослого, Sign Out.
- **Знакомство** — native `<dialog>`, 4 шага, Escape и пропуск. Выбор темы — только предпросмотр.
  При завершении или пропуске отправляется `PATCH /me {onboarding_version:1}`. При завершении тема ещё и добавляется в коллекцию (`POST /worlds` идемпотентен) и становится активной.
- **Тема** — светлая / тёмная / системная в header (и на экранах входа), `aria-pressed`; сохраняется в профиле через `PATCH /me {theme}`.

## Графики и доступность

- Палитры проверены валидатором dataviz (`src/shared/charts/palette.ts`).
  Категории в порядке макета: синий / бирюзовый / золотой. Для «Других занятий» в графиках используется `#eda100`, потому что `#FFD23F` не проходит по яркости для меток.
  В режиме «Предметы» цвет закреплён за занятием по его позиции в каталоге; после 7 занятий остальные сворачиваются в «Ещё занятия».
- У каждого графика есть легенда, подсказки при наведении и числовая таблица (relief для слотов ниже 3:1 в светлой теме).
- Используются кнопки и ссылки, кликабельные зоны ≥ 44 px, `:focus-visible`, подписанные поля, `role=alert/status` для ошибок и статусов. Статус не передаётся только цветом. Учитывается reduced-motion (через CSS макета).

## Проверено

- `npm run typecheck`, `npm run build`, `npm test` (все тесты в `src/**`). Покрыто:
  - CSRF, refresh, Idempotency-Key при повторе, `X-Child-Id`;
  - вход, настройка, переключение темы;
  - конфликт ревизии и сохранение > 24 ч у таймера;
  - линия без нулевых пропусков;
  - права на workload, проверенные записи и часовой пояс;
  - выход с `logout_incomplete` и при сетевой ошибке;
  - преобразование аналитики в графики.
- Маршруты и строгие схемы запросов сверены с кодом `backend/app` (только чтение).
- Живой backend без конфигурации: `/health/ready`, `/auth/csrf`, `/me` → 401, раздача `dist/`.
- Визуальная проверка в Chrome через Playwright на синтетических ответах API, перехваченных в браузере: 1440×900 и 390×844, светлая и тёмная тема, все экраны.
  Нет ошибок в консоли и горизонтального скролла страницы. Внутри мобильной таблицы кошелька допускается локальная прокрутка.

## Не проверено и ограничения

- **Реальная авторизация Supabase, БД и сквозные сценарии не проверены**: учётных данных нет.
  Не прогонялись реальные login/refresh/logout, два пользователя, конкурентные покупки и изоляция — их должен подтвердить QA на настроенной установке.
- Не реализовано (и на сервере, в `GET /settings → deferred`): AI-оценка и письмо хранителя, запись подключений `.env`, регистрация и восстановление пароля, связывание взрослых и детей, корректировки кошелька, исключения поручений, награды за чтение и свои цели.
  В UI это обозначено явно; поля секретов заблокированы.
- Таблица истории подгружается страницами по 100. Общее число записей считается из `daily-totals`.
- Выбор часового пояса ограничен списком зон РФ (плюс текущая зона профиля).
- Предупреждение о таймере, перешедшем полночь, решается выбором даты при сохранении. Автоматического деления сессии нет (по спецификации MVP).
- Бандл ~650 КБ (≈205 КБ gzip), основная часть — Unovis/d3. Code-splitting не делался. Source maps в production-сборку не включаются (`build.sourcemap: false`).

## Найденные несоответствия при интеграции

1. Без конфигурации `GET /me` → 401, а не 503. Обработано через `/health/ready` (см. выше). Расширять контракт не требуется.
2. Cookie `tfe_csrf` имеет флаг `Secure`. Для HTTP-разработки нужен `COOKIE_SECURE=false` (так и указано в API.md).
3. `dashboard.world.name/active_world` в коде backend могут быть `null`. Фронтенд защищён: подставляется тема `settlers`.
4. Флаги `can_edit_timezone`, `can_set_workload`, `can_delete_reviewed_entries` и ответ `503 logout_incomplete` добавлены backend после QA. Фронтенд их использует; при отсутствии флагов действия скрыты.
